# 性能改善の観点

このgroupは性能改善である。改善は計測で示す。計測しない最適化では、速くなったかどうかも、何かを壊していないかも示せない。

## implementer

- briefの計測方法 (コマンドと条件) をそのまま使う。briefに変更前の値が無ければ、変更前に同じ条件で測って記録する
- 変更後に同じコマンドと条件で測り、前後の数値と出力を `EVIDENCE` に書く。ばらつく指標は、briefの回数だけ繰り返して比べる
- 振る舞いを変えない。既存の検査をすべて通す
- 目標値に届かず、briefの範囲内で打てる手が無ければ、届いた値を添えて `BLOCKED` で返す。目標を下げるか範囲を広げるかは、人間が決めることである

## reviewer

次のどれかに証拠付きで反していれば、Acceptance Criterionの未充足 (項目9) としてREJECTする。

- 前後の計測が同じコマンドと条件で行われ、その出力が `EVIDENCE` にある。計測を自分で再実行してもよいが、時間がかかるなら出力の確認で足りる
- 計測の入力や条件だけを特別扱いする変更 (計測の入力に限ったcache、計測のときだけ省く処理) が無い
- 振る舞いが変わっていない
