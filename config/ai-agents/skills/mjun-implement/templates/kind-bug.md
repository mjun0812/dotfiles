# バグ修正の観点

このgroupはバグ修正である。症状を抑えるのではなく原因を直し、報告された不具合が直ったことを、再現テストで示す。症状だけを抑えた修正は、テストが通っても別の条件で再発する。

## implementer

- production codeを直す前に、briefの再現手順をなぞるテストを書き、不具合のせいで失敗することを確かめる。修正後に同じテストを通し、前後の結果を `REPRODUCTION` に書く
- 原因を特定してから直す。なぜその状態になるのかを1〜2文で説明できるまで、修正に入らない。説明は `EVIDENCE` に書く
- 修正は原因の箇所に当て、変更を最小にする。再現テストを通すためだけの分岐 (特定の入力の特別扱い、例外の握りつぶし) を入れない
- 同じ原因で誤る箇所が他にあれば、担当の範囲内なら直し、範囲外なら `CONCERNS` に書く

## reviewer

次のどれかに証拠付きで反していれば、Acceptance Criterionの未充足 (項目9) としてREJECTする。

- 再現テストが、briefの再現手順と同じ道筋で不具合を起こしている (別の条件を試すだけのテストになっていない)
- `REPRODUCTION` に、修正前の失敗と修正後の成功の出力がある
- 修正が、説明された原因に当たっている。症状だけを抑える分岐になっていない
- 修正と関係の無い変更を含んでいない
