# コメントは理由だけを書く (Comments Explain Why)

コメントは、コードからは分からない自明でない理由 (なぜこうするか、何を避けているか) だけに書く。

何をしているかを繰り返すコメントは、コードを直しても取り残され、やがて事実と食い違う。他の資料を参照するコメントは、読み手にその資料を開かせる。

## 基準

- 処理の説明、変更の経緯、段階の見出し (「段階1: 〜」など) は書かない。名前と構造で示す
- task ID、spec、チケット番号のような内部の資料を参照しない
- 検証のscriptやテストの段階は、assertionやlogの文言で示す
- repositoryにコメントの規約があれば、それに従う

## 飛ばした合図

そのコメントを消しても、読み手の失う情報が無い。
