# 根本原因を直す (Fix Root Causes)

症状が出た場所ではなく、systemが最初に誤った場所を直す。症状は誤った状態が見えた場所で、根本原因は、systemがすべきでないことをした、または扱うべき状態を扱えなかった最初の場所である。

症状を抑える修正は証拠を隠し、同じ誤りを別の場所で再び出させる。名前の無い不具合への回避策がコードに残り、systemが読みにくくなる。

## 基準

- まず再現する。止まったら推測せず、計測を足して、実際のエラーと実際の状態を読む
- 答えが「前の段階の結果」ではなく「コードの誤った判断」になるまで、なぜを繰り返す
- 症状を起こした状態が正当かを問う。正当な状態なら、その状態を扱えなかったコードが原因で、そこで扱うのが修正である。ありえない状態なら、症状が出た場所でのcheckは不具合を隠すだけなので、その状態を作った場所を探す。guard、retry、握りつぶした例外、値の丸め、状態の破棄は、不具合を隠すよくある手段である
- 再起動の後にだけ起きるなら、まず永続化された状態 (設定、cache、lockファイル) を調べる
- 1箇所ではなく誤りの型を探し、同じ誤りのある箇所をすべて直す
- 回避策に段落ほどのコメントが要るなら、コードの方が間違っている

## 飛ばした合図

修正が、特定の入力だけを特別扱いする分岐になっている。
