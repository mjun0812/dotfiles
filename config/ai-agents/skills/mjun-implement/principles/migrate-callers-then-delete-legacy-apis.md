# 呼び出し元を移してから古いAPIを消す (Migrate Callers Then Delete Legacy APIs)

新しい内部APIを入れたら、呼び出し元の移行と古いAPIの削除を、同じ変更で行う。互換層や、新旧の処理の並存を残さない。

残した古い処理は使われ続けて消せなくなり、後から読む人とagentが真似る見本になる。

## 基準

- 呼び出し元を全部移してから、古いAPIを消す。古い実装の細部だけを守るテストは消し、新しい契約を確かめるテストへ直す
- 名前を変えたら、文字列、文書、設定の中の参照まで、実際のファイルで確かめる。名前による検索は、これらを取りこぼしやすい

## 当てはめないとき

外部の利用者が古いAPIに依存している場合と、担当taskのBoundaryの外に呼び出し元がある場合。移せない呼び出し元は、構造化ブロックで報告する (implementerは `CONCERNS`、reviewerは `NOTES`、refactorerは `NOTES_SKIPPED`)。

## 飛ばした合図

新しいAPIの横に、古いAPIを呼ぶだけの関数が残っている。
