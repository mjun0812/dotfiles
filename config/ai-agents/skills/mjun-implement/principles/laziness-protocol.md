# 最小の差分にする (Laziness Protocol)

問題を解く最小の差分にする。同じ判断を何箇所にも書かず、1箇所で決めて結果を渡す。

差分が大きいほど、読む範囲、確かめる範囲、壊しうる範囲が広がる。同じ判断が散らばると、1箇所だけ直されてずれる。

## 基準

- 依頼とAcceptance Criteriaが求めない機能、設定項目、拡張点を足さない
- きれいに見える定型のコードより、短く直接的なコードを選ぶ
- 同じ条件や定数を2箇所以上で判定しているなら、1箇所で決め、値やflagで渡す

## 当てはめないとき

最小の差分が、既存の設計の歪みを広げる場合は、[前提から設計し直す](redesign-from-first-principles.md) を優先する。

## 飛ばした合図

差分に、どのAcceptance Criterionにも対応しない変更がある。
