# 読み手の負担を減らす (Minimize Reader Load)

保守のしやすさは、読み手がコードを理解するのに要る仕事の量で測る。辿る層の数と、頭に置いておく状態の量の2つを減らす。

行数や複雑度は代わりの指標にすぎない。浅くても状態の多いファイルは、層の深いコードと同じくらい読みにくい。

## 基準

- 呼び出し元が1つのwrapper、実装が1つしかないadapter、引数をそのまま渡すだけの層は畳む
- 状態の範囲を狭める。値を書き換えるより返す。module全体の状態よりfield、fieldよりlocalを選ぶ。同期させるより導出する
- 不変条件は、使う側ごとにではなく、境界で1回だけ名前を付けて示す
- 層や状態を足すなら、それが別の場所の負担を同じだけ以上減らすかを確かめる

## 目安

初めて読む人が「この値はどこから来るか」「何がこの値を変えるか」に30秒で答えられるか。

## 飛ばした合図
