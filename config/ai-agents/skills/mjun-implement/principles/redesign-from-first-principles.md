# 前提から設計し直す (Redesign from First Principles)

新しい要求を既存の設計へ継ぎ足さない。最初からその要求があったら何を作るかを考え、その形へ寄せる。

継ぎ足しを重ねると、どの要求のための形なのか分からない設計になる。

## 基準

- 影響するファイルを読み、今の設計を理解してから決める
- 変更を、型、呼び出し元、テスト、コメントまで、すべての参照へ行き渡らせる
- 設計し直すと担当taskの範囲を超えるなら、実装で回避せず、構造化ブロックで親へ返す。どこまで直すかはcontractの範囲で決まり、決めるのは親である

## 当てはめないとき

今の設計で素直に満たせるとき。設計し直すこと自体を目的にしない ([最小の差分にする](laziness-protocol.md))。

## 飛ばした合図

新しい要求のためだけの特別扱い (flag、分岐、引数) が、既存のコードの各所に散る。
