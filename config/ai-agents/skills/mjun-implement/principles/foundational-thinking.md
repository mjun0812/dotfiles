# 先にデータの形を決める (Foundational Thinking)

logicを書く前に、データ構造と型を決める。データの形が合っていれば、後のコードは自明になる。

構造の判断は、後から変えるほど高くつく。一方、コードの細部の判断は単純さを優先する。

## 基準

- 主な型とデータの形を先に決め、どこで書かれ、どこから読まれるかを辿る。よく通る処理に合う構造を選ぶ
- 型とデータの形は1つに収束させ、似た行は無理に共通化しない。似た3行は、早すぎる抽象化より良い
- 賢いコードより、明示的なコードを選ぶ
- 後のすべての作業が助かるもの (共通の型、テストの仕組み) は先に作る

## 当てはめないとき

設計で既に型とデータの形が決まっているときは、それに従う。

## 飛ばした合図

同じデータを、関数ごとに少しずつ違う形で組み立て直している。
