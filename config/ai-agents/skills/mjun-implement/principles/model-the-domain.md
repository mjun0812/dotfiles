# ドメインを構造で表す (Model the Domain)

散らばった条件分岐で表しているドメインの規則を、データ構造で表す。合った構造は不正な状態を表せなくし、分岐を消す。

書くときに構造を選ぶのは安い。後から取り出すとrefactoringになり、先送りされる。

## 手段

- 散らばったboolean、段階、ライフサイクルのcheck → state machine
- 緩い引数や、何箇所にも繰り返される形の前提 → 型付きのmodel
- ファイルをまたいで広がる分岐 → map、registry、lookup table、判別できるunion型
- その場しのぎの状態の書き換え → reducer、command / event
- 処理の順 (読む、検証する、変換する、保存する) で分けたmodule → 1つのドメインの知識でまとめたmodule。実行の順は所有の単位ではない
- どれも合わないときは、コードが決して許してはいけない状態と、データの読まれ方を書き出し、それをそのまま表す構造を探す

## 当てはめないとき

今の形が明快で局所的で、増える見込みが無いとき。分岐も、重複した規則も、不正な状態も減らさない抽象は足さない。

## 飛ばした合図

新しい機能で、既存のif/elseの連鎖に分岐が1つ増える。2つ目のbooleanを、1つ目と同期させる必要がある。
