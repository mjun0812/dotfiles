# 性能改善

計測で確かめることを重視する。計測しない最適化では、速くなったかどうかも、何かを壊していないかも示せない。

## 着手前に決めること

- **計測するもの**: 指標 (処理時間、メモリ、スループットなど) と、それを測るコマンド
- **計測の条件**: 入力の大きさ、環境、繰り返し回数、ウォームアップ。前後の条件をそろえるために決める
- **目標値**: どこまで改善すれば終えるか。依頼に無ければ、変更前の値を示して人間に聞く。どこで止めるかは価値判断なので、agentが決めない
- **変更前の値**: 決めたコマンドと条件で測り、briefに記録する。計測のコマンドを新しく作る必要があるときは、それを作って変更前の値を測ることを最初の完了条件にし、implementerに任せる
- **完了条件**: 同じ条件で目標値に届くこと、既存の検査がすべて通ること (振る舞いを変えない)

## 実装で確かめられること

mjun-implementは、briefが `kind: perf` のとき、implementerとreviewerに [性能改善の観点](../../mjun-implement/templates/kind-perf.md) を読ませる。implementerは同じコマンドと条件で前後を測って数値を報告し、reviewerはその出力と、計測の入力だけを特別扱いする変更が無いことを確かめる。目標に届かず範囲内で打てる手が無ければ、implementerは計測値を添えて止まる。目標を下げるかどうかは人間が決める。
