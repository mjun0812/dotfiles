# 証拠で確かめる

「直った」「動く」「速くなった」は、実際に実行して出力を確かめた証拠で示す。SubAgentの報告、コンパイルが通ったこと、推測は証拠にならない。証拠の無い主張を通すと、確かめていない変更が届く。

## 証拠の段階

届く中で最も上の段階で取り、どの段階で取ったかを記録する。上の段階ほど、後の変更でも自動で再発を捕まえられる。

1. **test**: 振る舞いをテストで確かめる。新しい振る舞いや直した不具合のテストは、変更前に失敗し、変更後に通る
2. **observation**: テストでは届かないとき、実物 (実ブラウザ、CLI、script) で手順をなぞり、変更前後の出力やスクリーンショットを取る
3. **instrumentation**: 手元で症状が起きないとき、ログや計測を足して発生条件を作り、仕組みが働く様子を変更前後で記録する

testより下の段階で終えたものと、見た目や操作感のように人間の目で判定するもの (目視) は、自動の再発防止にならない。それでも止まらずに進め、人間が確かめることとして証拠と一緒に報告する。

## 判断の基準

- 原因の仕組みが見えないまま、推測で直さない。直ったかどうかを示せないからである。止まるのは、計測まで試しても仕組みが見えないときだけにする
- 実行していないものの結果を書かない。実行しなかったものは、実行しなかったことと理由を書く
- 測れる量 (処理時間、メモリ) は、同じコマンドと条件で前後を測る。目視に回すのは、見た目や操作感の良し悪しだけにする

バグ修正での段階ごとの取り方は、mjun-implementの `templates/kind-bug.md` にある。
