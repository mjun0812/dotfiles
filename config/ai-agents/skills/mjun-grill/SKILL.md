# mjun-grill

計画・設計・specに残る意思決定を、ユーザーとの対話で1つずつ解決するSkill。文書 (specやIssue) の更新は行わず、決定内容を呼び出し元または会話へ返す。

## モード

- **設計全体モード** (デフォルト): 会話中の計画・設計・既存specを対象に、意思決定のあらゆる分岐点が解消されるまで質問を繰り返す。設計の分岐 (設計ツリー) を順に辿り、決定事項の依存関係を1つずつ解決する。「幅」より「深さ」を優先し、新たな洞察が得られなくなるまで1つのテーマを掘り下げてから次へ進む
- **単一decisionモード**: 呼び出し元から渡された1つのHuman-owned decisionだけを解決し、構造化したResolutionを返す。他の論点へ広げない

## Guidelines

- 質問は必ず一度に一つずつ行うこと。
- 質問には、推奨回答とその理由を必ず提示する。
- 質問の提示はTemplateに従うこと。
- ユーザーへの質問には ask_question / AskUserQuestion / request_user_input などのユーザーに選択を促すツールを使用する。いずれも使えない環境では、質問と数字付き箇条書きの選択肢を提示し、ユーザーの返信を待つ。
- 各質問の前に、コードベース・既存の規約・ドキュメントの関連箇所を調べる。**factsを集めるのはagentの仕事であり、調べれば分かることをユーザーに聞かない。**ユーザーに渡すのは、価値判断・スコープ・trade-offなど、調査では決まらないdecisionだけとする。
- 前提が未解決の質問を先に出さない。解決済みの前提の上に立つ質問だけを扱う。

## Template

```text
### Q[番号]: [質問文]

1. [選択肢]
2. [選択肢]
3. ...

**推奨: [1/2/...]**
**理由:** ...
```

## 設計全体モードの終了

- 論点を掘り尽くしたら終了を提案する。続行を求められれば続ける。
- 終了時に回答履歴をまとめて提示する。質問と回答の対応がわかるようにすること。

## 単一decisionモードの出力

呼び出し元から、decisionの論点・選択肢・関連する調査結果を受け取り、1問の質問として提示する。回答を得たら、次の形式で呼び出し元へ返す。

```markdown
## Resolution

- Decision: <論点>
- Owner: human
- Result: <ユーザーが選んだ決定>
- Rationale: <決定の理由 (ユーザーの回答と推奨理由から)>
- Remaining uncertainty: <残った不確実性。なければ「なし」>
```
