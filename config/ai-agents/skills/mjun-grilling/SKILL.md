# mjun-grilling

計画・設計・specに残る意思決定を、ユーザーとの対話で解決するSkill。ユーザーに委ねるのは、調査では決まらない判断 (価値判断、スコープ、trade-off) だけで、事実はagentが集める。ユーザーの時間を、調べれば分かることに使わせないためである ([原則](principles/asking-humans.md))。文書 (specやIssue) は更新せず、決定内容を呼び出し元または会話へ返す。

## モード

- 設計全体モード (デフォルト): 会話中の計画・設計・既存specを対象に、設計ツリーのすべての分岐が解消されるまでroundを繰り返す
- 指定decisionモード: 呼び出し元 (`mjun-specify` など) から渡されたHuman-owned decisionだけを解決し、decisionごとに `## Resolution` を返す。論点の洗い出しと反映は呼び出し元が持っているので、他の論点へ広げない

## 質問の前に調べること

事実がそろって初めて、質問は判断の問いになる。論点に関係する範囲で次を調べる。

- コードベース、既存の規約、ドキュメント
- `.mjun/steering/`
- 用語集 `CONTEXT.md` (repo直下にあればそれ、無ければ `.mjun/CONTEXT.md`)
- ADR (置き場所は [共通記録規則](../mjun-steering/references/glossary_and_adr.md#置き場所の決め方) で決まる `docs/adr/` か `.mjun/steering/adr/`)
- 対象specの `design.md` の `## Decisions`

superseded / deprecatedのADRと `Status: tentative` のdecisionは確定した規約ではないので、前提にしない。用語の衝突や有効なADRとの矛盾が見つかれば、それ自体を質問の論点にする。

## 質問の出し方

ユーザーが答えやすく、往復の少ない質問にする。

- 各質問に選択肢、推奨回答、その理由を添える。ユーザーは推奨を採るか退けるかで判断できる
- 前提が解決済みの論点だけを聞く。未解決の前提に立つ質問は、前提の答え次第で選択肢ごと無駄になる
- 互いに依存しない論点は1回にまとめて聞く。AskUserQuestionは1回に4問までなので、超える分も同じroundとして、他の論点の前提になっているものから順に続けて出す
- 選択を促すツール (AskUserQuestion / ask_question / request_user_inputなど) を使う。どれも使えない環境では、末尾のTemplateで提示して返信を待つ

## 設計全体モード

論点を設計ツリー (1つの決定から派生する決定の木) として持つ。frontierは、前提となる決定がすべて解決済みで、今すぐ聞ける論点の集合である。1 roundでfrontierをまとめて聞き、回答でツリーを更新し、新たに聞けるようになった論点で次のroundを組む。初回のfrontierは、計画・設計・specから洗い出した論点のうち前提を持たないものである。

ファイル、コード、外部仕様の調査が要る論点はSubAgentへ委譲し、結果を待たずに残りのfrontierを先に聞く。待つ間はユーザーの手が止まるためである。調査結果に依存する論点だけを後のroundに回し、結果が届いたらその下流をfrontierに加える。

frontierが空になったら終了し、それまでは終了を提案しない。残った分岐は、誰も決めていない仮定のまま実装へ持ち込まれる。ユーザーが続行を求めたら、論点の洗い出しからやり直す。

終了時は、質問と回答の対応が分かる形で回答履歴をまとめ、ユーザーに確かめないまま仮定した論点を残さない。ユーザーが共有理解に達したと確認するまで、決めた内容の実行 (実装や文書の更新) に移らない。実行は呼び出し元か次の依頼で行う。

## 指定decisionモード

呼び出し元から、decisionごとの論点、選択肢、調査結果を受け取る。agentの採択案が付いていれば、それを推奨として扱う。渡された調査結果で判断材料が足りないときだけ追加で調べる。別のdecisionの答えで選択肢が変わるdecisionは、前提の回答を得てから聞く。

回答を得たら、decisionごとに次の形式で呼び出し元へ返す。呼び出し元はこのブロックを読んで決定を反映する。

```markdown
## Resolution

- Decision: <論点>
- Owner: human
- Result: <ユーザーが選んだ決定>
- Rationale: <決定の理由 (ユーザーの回答と推奨理由から)>
- Remaining uncertainty: <残った不確実性。なければ「なし」>
```

## Template

選択を促すツールが使えない環境では、1 roundを次の形式で提示する。

```text
### Round [番号]

#### Q[番号]: [質問文]

1. [選択肢]
2. [選択肢]
3. ...

**推奨: [1/2/...]**
**理由:** ...

#### Q[番号]: ...
```
