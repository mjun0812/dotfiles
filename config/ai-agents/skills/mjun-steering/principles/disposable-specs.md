# specは使い捨て

spec (`.mjun/specs/`)、brief (`.mjun/briefs/`)、run (`.mjun/runs/`) は、作業中にだけ使う文書である。人間が承認した判断と、Agent同士の作業の受け渡しを支えるが、作業を終えた後に読む人はいない。実装済みの振る舞いを定めるのはコードとテストで、古いspecを根拠にすると、その後の変更を知らない文書へ従うことになる。

## 残すものの置き場所

作業を終える前に、残す価値のあるものを次の場所へ移す。移さないまま終えると、specと一緒に失われる。

| 残すもの                       | 置き場所                                             |
| ------------------------------ | ---------------------------------------------------- |
| 振る舞い (Acceptance Criteria) | テスト。目視で確かめるものは、PRの画像と説明         |
| 覆しにくい判断の理由           | ADR (3条件を満たすものだけ)                          |
| 語彙                           | 用語集 `CONTEXT.md`                                  |
| 何を、なぜ、どの範囲で作ったか | Issue (承認した判断シートとAcceptance Criteria)      |
| 変更ごとの理由と、確かめた証拠 | PRとcommit                                           |
| 後で取り組むもの               | Issue (作業の最後に、人間が選んだものだけを起票する) |

ADRにしない判断は、specに置いたままでよい。将来の読み手に要る判断かどうかは、ADRの3条件がすでに選り分けている。

## 判断の基準

- `status: done` のspecは、逆引き、一覧、境界の比較、依存の判定に使わない。残っていても消えていても、skillの挙動を変えない。削除は人間が手で行う
- 依存先のspecが見つからなければ、作業を終えた後に削除されたものとして扱う
- 既存の機能を拡張するときは、古いspecではなく、今のコード・テスト・Issueから新しいspecを作る
