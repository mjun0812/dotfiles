# 評価基準の変更記録

criteria.md が現在の基準の唯一の正本であり、このファイルは基準の変更のうち、旧基準に合わせて書かれた箇所 (痕跡) が各skillに残りうるものだけを記録する。判定にはcriteria.mdだけを使い、このファイルは痕跡の検出と根拠の表示にだけ使う。記録した時点のcriteria.mdは `scripts/criteria.baseline` にそのまま保持され、`scripts/check_criteria.sh` が現在のcriteria.mdとの差分を取る。

既存entryの本文は書き換えない。全件評価で痕跡が1件も見つからなくなったentryは削除する。同じ観点についての新しいentry (上にあるもの) が古いentryを上書きする。

## entryの形式

- 見出し: `## YYYY-MM-DD <観点>: <要約>`
- 種別: `強化` (要改善シグナルが増えた。痕跡は要改善)、`廃止` (要求が消えた。痕跡は削除任意で減点しない)、`緩和` (禁止が解けた。痕跡は指摘しない)
- 変更: 旧 → 新
- 理由: なぜ変えたか
- 痕跡: 旧基準に合わせて書かれた箇所を見つけるパターン。評価対象のSKILL.mdや付属ファイルから確認できるものだけを書く
- 修正: 痕跡の直し方

## 2026-08-31 観点11: 共通機能のフォールバック説明を冗長シグナルに

- 種別: 強化 + 緩和
- 変更: 「固有機能に依存する場合は代替手段か『無ければスキップ』を書く」→ 主要クライアントが共通に持つ機能 (skill、SubAgent、AskUserQuestionのような選択質問ツール) には代替手段を要求しない。それらが無い環境についての説明は要改善シグナル
- 理由: Claude Code / Codex / Gemini CLIのいずれもskill・SubAgent・選択質問ツールを持ち、全skillに同じ定型文を撒く冗長さだけが残っていた
- 痕跡: 「SubAgentが使えない環境では〜」「AskUserQuestionが使えない環境では〜」「Skill toolが使えない環境では〜」の文。選択肢をテキストで提示するためだけのテンプレート節
- 修正: 文ごと削除する

## 2026-08-31 観点10: 付属スクリプトのLinter・Formatterと実行確認

- 種別: 強化
- 変更: パス・コマンドの実在確認だけ → 付属スクリプトに `shellcheck` / `shfmt -d` (Pythonは `ruff check` / `ruff format --check`) を適用し、副作用の無い引数で実行して動作を確認する
- 理由: 実在しても動かないスクリプトを見逃していた
- 痕跡: shellcheckの警告、shfmtの整形差分、bash 3.2で動かない構文 (`${var,,}` など)、`--help` や引数なしで異常終了するスクリプト
- 修正: 警告を解消し、bash 3互換に直す

## 2026-08-31 観点9: 参照表記の統一

- 種別: 強化
- 変更: 合格条件に「Phase, 手順, 節などの参照表記が統一されている」「引用や参照は地の文と明確に区別されている」を追加
- 理由: 人間がメンテナンスするときに参照先を追えない文書が増えていた
- 痕跡: 同じ節を「事前チェック2」「ステップ3」「4. 説明文の生成」のように別の呼び方で参照している箇所
- 修正: 見出しの番号付けに統一する

## 2026-08-31 観点8: 100行超referenceの目次要件を廃止

- 種別: 廃止
- 変更: 合格条件「100行を超えるreferenceファイルは冒頭に目次がある」を削除
- 理由: referenceは主にモデルが丸ごと読むかgrepするため目次の価値が低く、見出し変更で腐る
- 痕跡: referenceファイル冒頭の `## 目次` (出力物のテンプレートとして置かれた目次は対象外)
- 修正: 削除してよいが減点しない

## 2026-08-31 観点6: 外部URLを禁止

- 種別: 強化
- 変更: 「外部URLや外部サービスへの依存は極力避ける」→ 外部URLを参照しない。必要な内容はskill内へ複製する
- 理由: skill-reviewはWebFetchを持たず到達確認ができないため、存在自体を禁止して判定を機械的にした
- 痕跡: SKILL.md・referencesの `http://` / `https://` (テンプレート内の `https://...` `https://example.com` のようなプレースホルダは対象外)
- 修正: リンク先の必要な内容をskill内の付属ファイルへ複製し、URLを削除する

## 2026-08-31 観点1・観点2: 内部動作を書かず、descriptionを書き写さない

- 種別: 強化
- 変更: 観点1の合格条件に「具体的な作業手順や内部動作について述べず、skillが実現することのみを記述する」「descriptionの書き写しはせず、より詳細な目的を述べる」を追加。観点2の合格条件に「具体的な作業手順や内部動作について述べない」を追加
- 理由: descriptionはroutingの判断材料であり、SubAgent構成やPhase列挙は発動判断に寄与せずTokenを消費する。目的文がdescriptionの複製なら情報が増えない
- 痕跡: descriptionや目的にSubAgentの構成・Phase列挙・worktree作成などの内部動作が書かれている。目的の1文目がdescriptionと同文
- 修正: descriptionは成果と発動条件だけにし、目的は「何を保証し、何をしないか」で書く

## 2026-08-28 観点10 (旧): dry-run観点を廃止

- 種別: 廃止
- 変更: 観点10「dry-run」を削除し、鮮度を観点10、クライアント互換性を観点11に繰り上げ
- 理由: 「dry-runが無いこと自体は減点しない」となった後、残った「外部反映の予測可能性」は観点4の完了条件で足りる
- 痕跡: 旧基準を満たすために追加された `--dry-run` 引数と、その分岐の手順
- 修正: 削除してよいが減点しない。残す場合は書き込みをスキップする範囲を明記する
